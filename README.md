# 飞书多维表「记录链接生成器」自定义组件

为飞书多维表（Bitable）制作的自定义组件：一键为**每一行**生成可被直接打开的「记录链接」，并写回到对应行的指定列。纯静态前端，可部署到任意静态托管（默认 GitHub Pages），在多维表「自定义组件 → 填写网址」处填上网址即可使用，无需后端、无需应用凭证。

## 功能

- **可选数据表**：组件加载后列出当前多维表下的所有工作表（数据表），可下拉切换要处理的工作表，默认选中当前激活表。
- **标准记录链接**：为每一行生成飞书「复制记录链接」的标准分享链接。链接通过 SDK 官方的 `table.getRecordShareLink(recordId)` 获取（返回含 24 位规范 recordId 的 `https://<域名>/record/<recordId>`，与飞书「复制记录链接」完全一致），**不会**退化成「整个表格的链接」，也**不会**出现「页面不存在」（注意：`getRecordsByPage` 返回的 recordId 只是客户端临时 id，不能直接拼 URL，必须走 `getRecordShareLink`）。
- 将链接写回到你指定的「目标字段」列。**目标字段必须是「超链接」类型**，链接才会显示为可点击的飞书记录链接。写入时按飞书 SDK 的 URL 字段取值规范（纯链接字符串，SDK 也兼容 `[{type:'url',text,link}]` 数组）写入，并**写后回读校验**确认确实存进了可见值，杜绝「报成功却没写入」的假成功。
- 可选「源字段」：仅处理该列非空的行（对应“分享记录”列），其余跳过。
- 进度条 + 运行日志，失败行单独提示。
- 字段可配置，适配任意表结构。

## 本地开发

```bash
npm install
npm run dev        # 本地预览（需在飞书多维表 iframe 环境内才会真正连到表格，本地仅看界面）
```

## 构建

```bash
npm install
npm run build      # 产物输出到 dist/，可直接作为静态站点托管
```

## 部署（GitHub Pages，gh-pages 分支方式）

本仓库使用「分支 gh-pages」托管 Pages：把构建产物 `dist/` 推到 `gh-pages` 分支即可，无需改仓库设置。

```bash
npm install
npm run build                 # 生成 dist/（含 .nojekyll）
# 把 dist/ 内容推送到 gh-pages 分支（可用 gh-pages 工具或手动）：
npx gh-pages -d dist -t true  # -t true 保留 .nojekyll
```

发布后站点地址形如：`https://<用户名>.github.io/<仓库名>/`，例如本仓库为
`https://yunjueyin.github.io/feishu-rowlink-plugin/`。该地址即为「自定义组件」要填的网址。

> 若飞书提示组件域名受限，请确保填入的是仓库 Pages 的 HTTPS 地址，并在飞书侧按需将该域名加入允许列表（通常自定义组件接受任意 HTTPS 网址）。

## 在飞书多维表中使用

1. 打开一个多维表，进入「自定义组件」（或在表格视图侧边栏添加组件）。
2. 选择「通过网址添加 / 填写网址」，粘贴上面的 Pages 地址并确认。
3. 组件加载后：
   - 在「数据表」下拉中选择要处理的工作表（默认已选中当前激活表）。
   - 选择「目标字段」（写回链接的列，**必须用「超链接」类型**，否则不会显示为可点击链接）。
   - 如需只处理有内容的行，选择「源字段」。
   - 点击「开始生成」，链接会逐行写回目标列。
   - 若组件未能自动识别飞书域名（如知识库 wiki 内嵌场景），在输入框填写飞书域名（如 `www.feishu.cn`）即可。
   - **运行日志**：点击「开始生成」后，日志首行会显示「已读取 N 条记录」。若 N=0，说明组件未读取到当前表的记录（请确认组件是添加在「包含数据」的工作表上，且当前选中的表确实有数据）；若 N>0 但目标字段不是「超链接」类型，日志会提示改用超链接字段。

## 说明

- 生成的「记录链接」形如 `https://<域名>/record/<recordId>`，与飞书「复制记录链接」导出的格式一致，点击即可在飞书内打开对应行记录。
- 写入为串行执行，避免触发飞书并发写入限制。
- 组件自动从运行时页面地址解析飞书域名；知识库（wiki）等不含标准飞书域名的场景，需手动填写飞书域名。
